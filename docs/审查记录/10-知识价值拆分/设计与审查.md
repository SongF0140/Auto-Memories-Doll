## 来源证据

- `extract()` 返回 `ExtractedCard[] | null`，null 同时表示"降级""解析失败""模型判定无内容"三种含义，调用方无法区分空结果与错误（第 9 块审查已登记该债）。
- 学习任务处理器恒无注入（第 9 块刻意留白）：任务永久 queued，无真实价值判断；`LearningTaskProcessor` 返回 `string` 摘要，无法承载逐卡结构化结果。
- 任务表无结果列：即使处理器产出知识也没有持久化位置。
- orchestrator 三处调用 `extraction.extract()`：573 行旧记忆优化候选（null/空 → 保守清理候选）、778 行 ingest 抽取（null → review 转人工，归因文案单一）、996 行人工放行后重抽取（null → 原样落盘）——三处对"空"与"错"的处置混在一起。
- 话题分类服务已有白名单 + 降级回退（classify 输入含 suggestedTopic 字段），学习链路尚未接入。

## 设计取舍

1. **判别联合契约**：`TurnAnalysisResult = {type:"skip",reason} | {type:"knowledge",items:TurnAnalysisCard[]} | {type:"unavailable",reason}`。skip 必带非空 reason（不可静默）；knowledge cards 数组 min(1)（空数组判解析失败，与 skip 不混淆）；unavailable 用于降级、输入超限、调用失败、解析耗尽——四种不可用各自携带可读原因。模型输出层 Zod schema 逐字段受校验：缺字段、越界枚举、非法结构一律判解析失败进重试，提示词注入文本无法绕过 schema。
2. **证据逐字校验**：每卡 `evidence:{sourceRole,text,verified}`，`verified = 原文.includes(evidence.text.trim())`（user/assistant 按 sourceRole 定位）。无 evidence、verified=false → `reviewStatus:"manual"` + `reviewReason` + kind 强制降为 `inference`（模型断言不可自动接受）；有 verified 证据才允许 `auto` 且保留模型 kind。历史上下文仅供消歧（prompt 标注"严禁从中提取卡片"），历史文本做证据因不在本轮原文必然 verified=false——防旧上下文知识混入。
3. **上限不静默截断**：单轮输入 > 24000 字符 → unavailable（不截断不分析）；输出 > 8 卡 → 整轮 unavailable（不 slice 后部分保存）；单卡正文 > 20000 → 整轮 unavailable。全部注明"需人工处理"，与"不静默截断保存"路线要求一致。
4. **处理器签名联合兼容**：`LearningTaskProcessor` 返回 `TurnAnalysisResult | string`——字符串维持第 9 块"completed+摘要"兼容语义；skip → completed+`无新增知识：<reason>`；knowledge → completed+`产出 N 张知识卡（自动 X / 人工 Y）`+result_json；unavailable → failed+原因，不自动重试（与处理器抛错同路径）。**零 pending_events 污染**：服务层处理路径不触碰 pending_events。
5. **result_json 加法迁移**：try/catch `ALTER TABLE ADD COLUMN result_json TEXT`（沿用 memory-service 先例）；`mapRow` JSON.parse 失败诚实返回 null（存储损坏不谎报有结果），result_summary 始终保留人可读摘要。
6. **extract() 显式三态**：`{status:"ok",cards} | {status:"empty",reason} | {status:"unavailable",reason}`；parseCards 拆出 empty（memories 数组存在但为空——模型明确判定无内容）与 invalid（JSON/结构坏、有效卡全被丢弃）。三处调用方行为保持：573 空/不可用 → 保守清理候选（附 audit 日志）；778 空/不可用 → 仍 review 转人工但归因可区分（"无内容可拆" vs "抽取不可用"）；996 空/不可用 → 人工已放行兜底原样落盘（补 audit 日志）。
7. **worker 构造即注入**：默认依赖链 `ConversationLearningService + MemoryExtractionService`（内含默认 TopicClassificationService），`setProcessor((task)=>analyzer.analyzeTurn(task))`；新增 `pollIntervalMs` 可调参数（默认 10000 不变），测试注入小值。instrumentation 无改动。
8. **非目标**：不改 quality-filter-service；知识卡不落 pending_events；reviewStatus 消费方（自动管线 vs 人工队列分流）留待第十一块；`analyzeTurn` 的 `recentHistory` 参数本块不接线 hook。
