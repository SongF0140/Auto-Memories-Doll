## 设计取舍

1. 用 Node 标准库 `spawnSync` 和 `node:test`，不引入 Husky、执行器框架或新依赖。
2. `verifyBlock(execute)` 仅注入执行器以测试编排；固定步骤私有，CLI 不接受任意命令，也不提供跳过项。同步执行避免上一块 build/typecheck 的生成目录竞争。
3. Windows 用 `npm.cmd` 和 shell，Linux 用 `npm` 且不启用 shell。shell 参数全部来自固定内部列表，未拼接用户输入；工作目录定位到脚本所在项目根，而非调用者目录。
4. 首个非零 status 原样返回；启动器抛错、返回 error 或信号终止导致空 status 返回 1。CLI 将结果写入 `process.exitCode`。
5. hook 使用 POSIX `sh` 与 `exec node` 传播状态；只创建仓库模板，不安装、不更改 `core.hooksPath`。
6. CI 只在现有 Windows/Ubuntu Node 22 checks 添加治理测试，不重复全构建，也不删除原门禁。
7. `.gitignore` 已精准预留本记录，不为形式再改；私人目录和数据保护不变。
