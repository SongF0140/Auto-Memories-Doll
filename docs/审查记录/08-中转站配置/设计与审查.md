本块目标：用户可配置 OpenAI 兼容中转站并保存生效。范围限定服务端闭环：a) 默认 AI 配置来源统一为 env seed（`getDefaultAiConfig()` 对齐 `src/config/env`），消除硬编码 openai 官方端点 + 空 Key 的首次 seed；b) api.config.ts 清理 baseURL/apiKey/模型名残留，持久配置成为凭证唯一来源；c) POST /api/config/ai 支持 apiKeyIntent / embeddingApiKeyIntent 三意图（keep/replace/clear），解决此前 schema min(1) 导致 Key 无法清除的问题；d) 守护测试锁定既有正确行为。不动 domain/service 层设计，不动 provider 调用链，不改 UI 表单（见未验证边界）。

## 来源证据

- `src/config/env.ts`：已有 MODEL_API_KEY / MODEL_BASE_URL，但第七块之前 `getDefaultAiConfig()` 硬编码 `https://api.openai.com/v1` + 空 Key——env 凭证在整个 AI 调用链中从未接入持久配置。
- `src/lib/validation.ts`：`apiKey: z.string().min(1)` 使"清除 Key"在任何路径上都不可表达（只能传错值）。
- `src/app/api/config/ai/route.ts`：GET 已做 `****`+尾4脱敏；POST 直接 safeParse 落库，无意图语义。
- `src/config/api.config.ts`：残留 baseURL/apiKey/flagship/standard/budget 三块硬编码，与持久配置构成第二个互不一致的潜在消费点（grep 确认当时无人消费）。

## 设计取舍

1. **默认值唯一来源**：`getDefaultAiConfig()` 从 env seed（baseURL=MODEL_BASE_URL、apiKey=MODEL_API_KEY、tier 模型取 FLAGSHIP_MODEL/STANDARD_MODEL/BUDGET_MODEL、embedding 取 EMBEDDING_MODEL，均有回退默认）。env 只在首次 seed 流入，持久配置优先——单一写入点，符合"SQLite 为长期真源"。
2. **api.config 只留运行参数**：保留 concurrency/degradation/embedding 元数据（generator.ts 用 embedding.name 打标，model-adapter 用并发与降级），删除凭证与模型名，消灭 env 凭证第二个消费点。
3. **Key 三意图**（api-and-interface-design 的边界校验原则）：`keep` 回填库存真实 Key（前端表单含密码框回显场景）、`replace` 用新值（空值 400）、`clear` 置空。省略意图时按掩码回填兼容旧客户端——不传 intent 的前端仍能"不改 Key 直接保存"。intent 是保存指令，parse 后显式 delete，不入库。
4. **掩码回填防静默损坏**（独立审查 Minor-1）：掩码形态（`****` 开头）但尾4与库存不匹配（Key 已轮换）→ 400 拒绝，绝不把掩码当真实 Key 入库。修复前该场景会静默写坏配置。
5. **短 Key 防泄露**（独立审查 Note-2）：`maskKey` 仅当 Key 长度 >4 才保留尾4，否则整体 `****`——避免 4 位以下 Key 被掩码完整暴露。
6. **任意模型名放行**：不强制命中 provider catalog（中转站自定义模型名是常态），守护测试锁定。

## 前端现状与未验证边界

- **AiConfigForm.tsx 本块未改动**：表单不传 intent，保存时走掩码回填兼容路径——改 Key（输入新值）与不改 Key（掩码回填）均正常，闭环成立；唯一不可达操作是"清除 Key"（空串 + 无 intent 被 400 拦截，与改动前行为一致，非回归）。intent 的 UI 集成（如"保留当前 Key / 替换 / 清除"选择）交由后续 UI 重做块（13-17）或用户指示后补做。
