# 11 — 逐知识匹配、融合精修与冲突审核设计与审查（加速交付版）

## 授权、范围与状态

2026-10-05，依据批准路线第 11 块实现，用户明确要求加速交付（一小时窗口、测试瘦身、捷径入档、最后统一验证）。未安装依赖、未访问真实密钥/模型/网络/私人数据库。加载 test-driven-development。

本块目标：a) 新增 `knowledge-reconciliation-service.ts`，逐卡 duplicate/supplement/new/conflict 判定；b) 相似度只召回候选（上限 5 张完整卡），移除 orchestrator 两处 cosine≥0.95 直接拒绝捷径；c) supplement 产出完整精修卡，同目标同轮强制合并；d) 无依据 assistant/mixed 新增断言强制 review；e) 接受/待确认分开计数；f) worker 学习链路接线：analyzeTurn → auto 卡协调 → stage 通路落候选。

## 设计取舍

1. **判定归 LLM、相似度只召回**：`ReconciliationRecall` 注入召回函数（完整卡），单次 flagship 调用对全部 auto 卡 × 候选集出决策数组；Zod 判别联合校验输出。
2. **契约硬约束（违反判解析失败→重试→unavailable）**：targetId 必须来自召回集合（模型不可虚构）；decisions 数量=输入卡数；同目标 supplement 唯一（同轮补充必须合并成一张精修卡）。
3. **不信任模型自报**：new 决策若卡为 assistant/mixed 且无 verified 证据，服务端强制 review=true（enforceNewReview）。
4. **计数口径**：duplicate=信息已在库；accepted=new 且 review=false；pending=review-new + supplement + conflict。冲突不覆盖既有卡。
5. **worker 落候选（stage 通路）**：new → stageCreateMemory（chat 来源，带 kind/evidence 元数据）；supplement → stageUpdateMemory（既有卡走审计更新）；conflict/review-new → 同落 create 候选交既有闸门/审计裁决；单条落库失败 warn 不中断其余。协调摘要（duplicates/accepted/pending/unavailableReason）附加进 result_json。
6. **orchestrator 捷径移除**：更新路径与 ingest 新建路径的 `VECTOR_DEDUP_SIMILARITY=0.95` 直接拒绝分支删除；RECALL_TOP_K 3→5；召回失败仍 fail-closed（新建转 review、更新记日志走审计）。重复/新颖性判定归质量闸门 LLM。

## TDD 证据

- 红灯：`knowledge-reconciliation-service.test.ts` 10 用例先写（服务不存在全红）；绿转期 1 个失败暴露"信任模型自报 review"缺陷 → 加 enforceNewReview（先复现失败再修）。
- worker 集成 2 用例：knowledge → 协调 → stageCreateMemory 落候选 + result_json 摘要；协调不可用 → 任务仍 completed、pending 计数 + 原因。
- 既有用例改写：orchestrator.test "向量去重≥0.95 rejected 不调闸门" → 改为"高相似不再直接拒绝，作为提示进闸门由 LLM 判重复"。
- 目标测试结果：worker(5) + reconciliation(10) + orchestrator(45) = 60/60 通过。

## 加速捷径（待第 18 块统一验证与精修）

1. **门禁未跑**：typecheck/lint/format/build/全量 test 全部推迟到所有板块写完后统一执行（用户指令）。
2. **conflict 与 review-new 落 create 候选**而非独立冲突队列：依赖既有闸门 fail-closed 把关，人工队列分流留给 UI 块（14-16）。
3. **supplement 精修卡未做 topic 白名单二次分类**：直接采用模型输出的 topic（可能越界）。
4. **worker 私有 recallCandidates 与 orchestrator.recallSimilarMemories 逻辑重复**（embedding+VectorIndex+getMemory）：低耦合优先，后续统一。
5. **同步协调调用在 worker 处理路径内**：单轮多卡时召回为串行循环（每卡一次 embedding），成本可控但未批量化。
6. **correction.ts / retriever.ts 未按路线图扩展**（跨源因果边解析留给后续）。
