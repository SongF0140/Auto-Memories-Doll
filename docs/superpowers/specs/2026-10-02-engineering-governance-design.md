## 目标与边界

建立编号需求、决策理由、验证证据、人工审查、小步提交的可解释闭环。沿用 Next.js/TypeScript、现有测试和 CI，不新增依赖。

本轮不修改 AgentLoop、map、存储架构、数据库或业务验收，不升级框架，不导入第三方源码，不推送。工程规范保留根目录 `Agents.md` 原名，业务主题 `Agent.md` 不承载工程规则。

## 设计取舍

1. **渐进治理而非并行重构业务**：先建立可审查流程，避免治理改动与 AgentLoop/map 行为纠缠；成本是业务改进另轮设计。
2. **既有 specs + 每块一个聚合审查文件**：记录设计、AI coding、证据、人工历史，避免独立 SPEC/rules/ADR 重复真源。
3. **精确白名单而非开放全部 docs**：逐层放行一个规格和三个指定审查文件，其他私人历史文档保持忽略。新增治理路径须显式审批及实测。
4. **保留 Agents.md**：用户最新路径确认覆盖原计划的大小写重命名；修正贡献入口，不制造同义规范。
5. **先登记存储冲突**：历史 Markdown 主存储、不可变追加表述与后期 SQLite 真源及覆盖更新记录不一致；本轮不通过修改实现或抹去历史消除冲突。
6. **跨平台 Node 门禁（第二块已实现）**：标准库固定运行 `typecheck → test → lint → format:check → build`，首个失败非零退出并停止；治理测试通过 `npm run test:governance` 另跑，五项入口为 `npm run verify:block`。不复制 Java/Maven、Claude Bash hooks 或失败多次后放行。Git hook 仅为可选且未安装的模板，不承诺 Trae 自动拦截；Windows / Node 24 本机实测不证明 Linux、Node 22 或远端 CI 已通过。

## 保护边界与失败处理

规格、验收断言、门禁、CI、覆盖率阈值不得为获取绿灯被任意改变。初始化修改仅限批准计划列出的内容；后续变化先获得用户批准并保留原审查意见。

基线失败或缺依赖先记录并停止，不能盲目安装、塞入密钥或减少检查。文档板块不伪造红绿业务测试，用 ignore、链接、差异及现有测试/构建验证。日志只记脱敏摘要。

本地验证不证明远端 CI、E2E、真实模型或 hook 生命周期。证据按环境分开，未运行项明确标未验证。
