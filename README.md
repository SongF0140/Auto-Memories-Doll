# Auto-Memeries-Doll

## 项目概览

这是一个以本地记忆管理、提示词编辑、索引检索和审计写回为核心的项目。系统围绕“前端交互 -> 结构化处理 -> 本地持久化”展开，目标是把用户输入、外部接入和后台任务统一到可追踪、可回放、可恢复的本地工作流中。

## 总体架构

项目按职责分为四个处理面：

- 入口层：接收用户输入，处理模式切换和提示词编辑。
- 快轨层：处理低延迟交互和流式输出。
- 后台加工层：负责清洗、分类、打分、索引构建和记忆提取。
- 审计持久化层：负责比对、冲突处理、版本管理和写回落盘。

四层关系固定：入口层只负责接入，快轨层只负责即时响应，后台加工层只负责结构化处理，审计持久化层只负责最终写回和归档。

## 数据流

### 前端会话

用户在前端发起对话或编辑提示词后，输入先进入入口层，再根据任务类型进入快轨层或后台处理链路。快轨链路直接返回流式结果；后台链路会生成结构化数据、索引和可写回结果，再进入审计持久化层。

### 外部接入

来自 MCP、skills 或浏览器采集的数据，会先进入入口层或后台加工层，再被拆分、清洗、分类和归档。结构化结果可以进入记忆文件、索引地图、标签索引和向量索引。

### 后台任务

定时任务、批处理和异步工作流主要进入后台加工层，再交给审计持久化层完成本地写回。后台任务的目标不是立即响应，而是保证数据完整性和可追踪性。

## 目录结构

- `src/app`：页面和路由入口
- `src/components`：可复用 UI 组件
- `src/features`：业务功能实现
- `src/lib`：基础能力与适配层
- `src/server`：服务编排、任务和管线
- `src/types`：共享类型
- `src/config`：环境与常量
- `notes`：项目架构说明和设计补充
- `archive`：历史版本和归档内容

## 本地存储

系统以本地文件夹承载记忆数据，核心结构如下：

```txt
memory-root/
├─ index-map.md
├─ profile.md
├─ notes/
│  ├─ topic-a/
│  │  ├─ Agent.md
│  │  ├─ note-001.md
│  │  └─ note-002.md
│  └─ ...
└─ archive/
```

### 文件职责

- `index-map.md`：目录总索引、标签入口和引用路径
- `profile.md`：偏好、标签和检索偏置
- `notes/*/Agent.md`：主题摘要
- `notes/*/note-*.md`：具体记忆内容
- `archive/*`：历史版本、分支版本和回滚副本

## 处理规则

- 先更新具体记忆，再同步摘要，再更新索引。
- 写回顺序不得反过来。
- 归档快照必须包含时间戳和原因。
- 新文件必须放到对应职责目录，不得跨层堆放。

## 接口边界

- `chat/route.ts`：快轨对话入口
- `memory/route.ts`：记忆读写入口
- `prompt/route.ts`：提示词更新入口
- `ingest/route.ts`：后台数据接入入口
- `audit/route.ts`：审计入口

## 数据模型

核心数据对象包括：

- `MemoryRecord`：记忆主记录
- `VectorRecord`：向量索引记录
- `GraphEdge`：关系边
- `MemoryVersion`：历史快照索引

这些类型的详细约束和行为规则见 `Agents.md`。
